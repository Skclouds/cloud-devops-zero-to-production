
## Engineering Competency Standard

This repository follows a production-oriented engineering learning methodology.

The objective is to develop the technical depth and operational confidence expected of an engineer with approximately two years of Cloud and DevOps experience, while establishing a foundation for future MLOps specialization.

### Teaching Methodology

Every technology and concept is studied through the following layers:

1. **Technical Fundamentals:** Understand the underlying concepts, terminology and engineering principles.
2. **Architecture and Internals:** Understand components, execution flows, dependencies and interactions.
3. **Configuration and Implementation:** Configure and operate the technology independently.
4. **Command Mastery:** Understand command syntax, options, outputs, logs and error messages.
5. **Real-World Engineering:** Implement realistic applications and infrastructure workflows.
6. **Troubleshooting:** Diagnose failures through systematic investigation and evidence.
7. **Root Cause Analysis:** Identify underlying causes rather than treating symptoms.
8. **Recovery and Prevention:** Restore services and implement preventive measures.
9. **Security and Best Practices:** Apply reliability, security and performance principles.
10. **Independent Assessment:** Solve unfamiliar technical scenarios without guided instructions.

### Production Troubleshooting Standard

Every module must include scenarios involving:

- Configuration failures.
- Resource exhaustion.
- Application failures.
- Network connectivity issues.
- Authentication and authorization failures.
- Dependency failures.
- Performance degradation.
- Deployment failures.
- Monitoring and alerting failures.
- Recovery and rollback procedures.

### Practical Competency Requirements

A topic is not considered mastered merely because its commands have been executed.

The learner must be able to:

- Explain how the technology works.
- Justify engineering decisions.
- Implement configurations independently.
- Interpret logs and diagnostic output.
- Identify and isolate failures.
- Resolve realistic incidents.
- Verify service recovery.
- Document technical findings.

### Learning Quality Policy

- No superficial command memorization.
- No tutorial-only completion.
- No unsupported claims of production experience.
- No skipping technical fundamentals.
- No marking a topic complete without practical verification.
- All practical exercises must respect the strict $0 cloud infrastructure budget.

**Success is measured by independent engineering capability, not by the number of tools studied.**
